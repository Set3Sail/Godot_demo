## 1. 总体架构

### 1.1 场景层级

```
BattleScene (Node3D/Control)
├── BattleManager (Node)          — 顶层协调器，Autoload 引用入口
│   ├── TurnStateMachine (Node)   — 回合状态机
│   ├── CardManager (Node)        — 牌库/手牌/弃牌堆/消耗堆
│   ├── ResourceManager (Node)    — HP/精神力/魔晶/力量/敏捷
│   ├── EffectResolver (Node)     — 伤害/格挡/Buff/Debuff 结算管道
│   ├── RelicManager (Node)       — 遗物注册 + 时机触发器
│   ├── EnemyManager (Node)       — 敌人集合 + AI 调度
│   ├── EquipmentManager (Node)   — 装备槽管理（CardManager 子模块）
│   └── CharacterMechanics (Node) — 7角色机制（策略模式）
├── PlayerArea (Control)          — 手牌区 UI
├── EnemyArea (Control)           — 敌人展示区 UI
├── HUD (Control)                 — HP/精神力/魔晶/回合数
└── EffectsLayer (Control)        — 特效/动画/FX
```

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **信号解耦** | 模块间通过 Godot Signal 通信，而非直接方法调用 |
| **单帧结算** | 所有效果在同一帧内完成结算管道（Trigger → Modify → Execute），避免竞态 |
| **数据驱动** | 卡牌/遗物/敌人数据用 Godot `.tres` Resource 文件定义，逻辑与数据分离 |
| **无硬编码角色** | 角色机制通过策略模式注册，新增角色不修改框架代码 |

### 1.3 结算管道（核心循环）

```
出牌请求
  → 费用校验（ResourceManager）
  → 目标合法性校验（EffectResolver）
  → 触发"打出前"时机（RelicManager + 角色被动）
  → 执行卡牌效果（EffectResolver）
  → 触发"打出后"时机（RelicManager）
  → 卡牌入弃牌堆（CardManager）
  → 检查击杀/触发"击杀时"时机
```

## 2. 回合状态机

### 2.1 状态枚举与流转

```
BATTLE_START
  → PLAYER_TURN_START（抽牌、回精神力、遗物触发）
    → PLAYER_PLAY（出牌阶段，等待玩家操作）
    → PLAYER_TURN_END（弃手牌、移除格挡、减益-1tick）
  → ENEMY_TURN（按顺序执行各敌人意图）
  → ROUND_END（检查胜负/特殊结算）
  → PLAYER_TURN_START（循环）
  → ...直到 BATTLE_WIN / BATTLE_LOSE
```

### 2.2 各状态职责

| 状态 | 输入 | 处理 | 输出信号 |
|------|------|------|----------|
| `BATTLE_START` | 敌人阵容、牌组 | 洗牌→抽5张→触发"战斗开始"遗物 | `battle_started` |
| `PLAYER_TURN_START` | — | 精神力回满(3)·抽满5张·触发"回合开始"遗物/能力 | `player_turn_started(round)` |
| `PLAYER_PLAY` | 玩家点击卡牌 | 费用校验→目标选择→**结算管道**→检查手牌是否为空 | `card_played(card)` `end_turn_request` |
| `PLAYER_TURN_END` | — | 弃所有手牌→移除格挡→Buff/Debuff 计时-1→荆棘结算 | `player_turn_ended` |
| `ENEMY_TURN` | 意图队列 | 按顺序执行每只敌人意图（动画间隔 0.3s） | `enemy_acted(enemy, intent)` |
| `ROUND_END` | — | 检查 HP≤0→死亡/胜利·检查特殊结束条件 | `battle_won` / `battle_lost` / `new_round` |

### 2.3 抽牌与牌堆循环

```
draw_cards(count):
  drawn = []
  while drawn.size() < count:
    if 抽牌堆为空:
      if 弃牌堆为空:
        break  // 无牌可抽
      弃牌堆全部移入抽牌堆 → 洗牌 → 触发"洗牌时"时机
    drawn.append(抽牌堆.pop_top())
  drawn → 加入手牌
```

### 2.4 关键约束

1. 玩家可在 `PLAYER_PLAY` 状态主动结束回合（即使还有精神力）
2. 精神力不足时，卡牌灰色不可选，但仍可查看详情
3. 目标选择模式：
   - 无目标（自身/全局效果）：点击卡牌立即打出
   - 单目标（敌人/友方）：卡牌高亮 → 点击目标确认
   - 需要确认的目标在 `ENEMY_TURN` / `PLAYER_TURN_START` 期间不可操作
4. 敌人回合期间玩家不可操作（除遗物/能力被动触发）
5. 任何时候 HP≤0 立即触发死亡检查，不等待当前结算完成
6. 洗牌时机：抽牌堆为空且需要抽牌时触发（非回合开始就洗）
7. 洗牌触发"洗牌时"遗物/能力（如：洗牌时获得格挡）
8. 弃牌堆的顺序不影响洗牌结果——洗牌后随机排列
9. 手牌上限不做硬限制（由精神力约束出牌数量），但 UI 需支持 10+ 手牌展示

## 3. 卡牌系统

### 3.1 卡牌数据结构（CardData Resource）

```gdscript
# CardData.tres 字段定义
id: String              # 唯一标识 "yemo_forge_strike"
card_name: String        # 显示名 "锻造打击"
character: String        # 所属角色 "叶默" / "通用"
type: Enum               # ATTACK / SKILL / ABILITY / EQUIPMENT
rarity: Enum             # COMMON / UNCOMMON / RARE / EPIC / LEGENDARY
cost: int                # 精神力消耗 0-4
effects: Array[Effect]   # 效果列表（支持多效果）
keywords: Array[String]  # ["锻造", "荆棘"]
is_upgraded: bool        # 是否已营地升级
is_forged: bool          # 是否已锻造（叶默，临时）
forge_count: int          # 已锻造次数（默认0，上限1，可通过能力提升）
upgrade_version: String  # 升级后卡牌 id（营地升级指向新卡）
description: String      # 展示文本
art_path: String         # 卡面美术资源
```

### 3.2 Effect 结构（组合式效果）

```gdscript
# Effect 字段定义
type: Enum           # DAMAGE / BLOCK / DRAW / GAIN_ENERGY / BUFF / DEBUFF /
                     # HEAL / SUMMON / SPECIAL / MODIFY_STAT / REMOVE_STATUS
target: Enum         # SELF / SINGLE_ENEMY / ALL_ENEMIES / RANDOM_ENEMY / ALL_ALLIES
base_value: int      # 基础数值
scale_stat: String   # 受哪个属性加成（"strength"/"dexterity"/"none"）
repeat: int          # 执行次数（默认1，"3伤×2次"=repeat:2）
condition: String    # 条件表达式（可选，如 "target_has_mark"）
status_id: String    # 施加的 Buff/Debuff id（BUFF/DEBUFF 类型时填写）
status_stacks: int   # 状态层数
status_duration: int # 状态持续回合数（-1=永久/本场）
cost_hp: int         # 盛元血祭：打出时额外消耗 HP（0=不消耗）
```

### 3.3 卡牌生命周期

```
牌组初始（开局 12 张）
  ↓ 战斗开始
抽牌堆 ← 洗牌
  ↓ 抽牌
手牌 ← 打出
  ↓ 打出后
弃牌堆（普通卡） 或 消耗堆（消耗标签卡/能力卡/装备卡）
  ↓ 抽牌堆空时
弃牌堆 → 洗牌 → 抽牌堆（循环）
```

### 3.4 四大牌堆管理

| 牌堆 | 数据结构 | 可见性 | 操作 |
|------|----------|--------|------|
| 抽牌堆 | Array（有序，顶部=下一个抽到） | 不可见（背面） | pop_top / shuffle / insert |
| 手牌 | Array（无序） | 完全可见 | add / remove / upgrade_in_hand |
| 弃牌堆 | Array（无序） | 可查看 | add / move_all_to_draw |
| 消耗堆 | Array（无序） | 可查看 | add（不可恢复，除特殊遗物） |

### 3.5 卡牌操作接口

```gdscript
# CardManager 公共方法
draw_cards(count: int)                # 抽牌流程（含洗牌触发）
discard_hand()                        # 手牌全部入弃牌堆
discard_card(card: CardData)          # 指定弃牌
exhaust_card(card: CardData)          # 指定消耗（入消耗堆）
play_card(card: CardData, target)     # 进入结算管道
shuffle_deck()                        # 重新洗牌（仅抽牌堆）
add_card_to_deck(card: CardData)      # 战斗中新增卡（入弃牌堆）
add_card_to_hand(card: CardData)      # 直接入手牌（不经过抽牌堆）
remove_card_from_battle(card: CardData) # 从战斗中移除（不入任何堆）
upgrade_card_in_hand(card: CardData)  # 锻造/临时升级（叶默）
get_deck_count() -> int               # 总牌数（抽牌+手牌+弃牌）
get_hand_size() -> int                # 手牌数
```

### 3.6 关键约束

1. 消耗卡（能力卡/装备卡/消耗标签卡）打出后进消耗堆，本场不再循环
2. 同名卡可携带多张（如 5 张"斩击"），每张独立追踪状态
3. 锻造升级只改变本场实例，不修改 CardData 原数据
4. 营地永久升级：替换为 upgrade_version 指向的 CardData
5. 传说卡不可升级（upgrade_version 为空）

## 4. 资源管理器 & 效果结算器

### 4.1 ResourceManager

管理战斗中所有数值资源：

| 资源 | 类型 | 初始化 | 说明 |
|------|------|--------|------|
| HP | int | 角色基础值 ± 遗物修正 | ≤0 触发死亡 |
| MaxHP | int | 同上 | 战斗中可被遗物/事件修改 |
| 精神力(Energy) | int | 每回合回满 3 | 当前回合可用费用 |
| 力量(Strength) | int | 0 | 每点 +1 攻击伤害 |
| 敏捷(Dexterity) | int | 0 | 每点 +1 格挡 |
| 格挡(Block) | int | 0 | 回合结束时清零 |
| 魔晶(Crystals) | int | 0 | 击杀敌人获得，战斗结束后结算 |

```gdscript
# ResourceManager 公共方法
modify_hp(target, delta: int, damage_type: String = "normal")
modify_max_hp(target, delta: int)
modify_energy(delta: int)
modify_block(target, delta: int)
modify_strength(target, delta: int)
modify_dexterity(target, delta: int)
add_crystal(count: int)
get_effective_damage(base: int) -> int          # 基础 + 力量
get_effective_block(base: int) -> int            # 基础 + 敏捷

# 信号
hp_changed(entity, current: int, max_hp: int, delta: int)
energy_changed(current: int)
block_changed(entity, current: int)
crystals_changed(count: int)
strength_changed(value: int)
dexterity_changed(value: int)
entity_died(entity)
```

### 4.2 EffectResolver（结算管道）

```
出牌效果结算顺序：

1. TARGET_RESOLVE     — 解析目标（单个/全体/随机/最前排）
2. PRECONDITION       — 检查条件（目标存活/有标记/可被选中）
3. PRE_TRIGGER        — "效果生效前"遗物/能力触发
4. EXECUTE            — 按 Effect 类型分发执行
   ├── DAMAGE:        伤害 = (基础值 + 力量) × 倍率修正 × 易伤修正
   │                  格挡吸收部分 = min(伤害, 格挡)
   │                  实际扣血 = 伤害 - 格挡吸收
   │                  格挡 = 格挡 - 格挡吸收
   ├── BLOCK:         格挡 += 基础值 + 敏捷
   ├── DRAW:          抽 N 张
   ├── GAIN_ENERGY:   精神力 +N
   ├── APPLY_BUFF:    对目标施加 Buff（层数 + 持续回合）
   ├── APPLY_DEBUFF:  对目标施加 Debuff（层数 + 持续回合）
   ├── HEAL:          HP +N（不受力量/敏捷影响）
   ├── REMOVE_STATUS: 移除目标指定状态
   ├── MODIFY_STAT:   直接修改力量/敏捷
   └── SPECIAL:       角色机制自定义效果
5. POST_TRIGGER       — "效果生效后"遗物/能力触发
6. KILL_CHECK         — 目标 HP≤0 → 击杀奖励 + 遗物触发
```

### 4.3 关键规则

1. **神圣伤害(Holy Damage)**：跳过 EXECUTE 阶段的格挡扣除，直接扣 HP
2. **穿透(Pierce)**：伤害计算时，格挡视为 (格挡 - 穿透值)，最低为 0
3. **多重伤害（repeat > 1）**：每次独立计算格挡（如 "3伤×2次"对 5 格挡目标=每次 0+0）
4. **效果执行顺序**：卡牌上的 Effect 数组按定义顺序依次执行
5. **单次结算原子性**：一张卡牌的所有 Effect 间不插入其他卡牌/遗物回调
6. **伤害下限**：除非被格挡完全吸收，否则至少造成 1 点伤害
7. **反伤(Thorns)**：部分敌人/遗物在受到伤害时对攻击者造成反伤

## 5. 状态效果系统

### 5.1 通用结构

```gdscript
# StatusEffect 定义
id: String                # "strength_up" / "frost" / "vulnerable"
display_name: String      # "力量+" / "冰霜" / "易伤"
type: Enum                # BUFF / DEBUFF
stack_type: Enum          # INTENSITY（强度叠层） / DURATION（只续回合）
max_stacks: int           # 最大层数（-1 = 无上限）
default_duration: int     # 默认持续回合（-1 = 永久/本场战斗）
icon_path: String         # UI 图标路径
tick_effect: Array[Effect] # 回合结束时的效果（中毒/灼烧/荆棘等）
```

### 5.2 标准状态效果池（全角色通用）

| 状态 | 类型 | 叠层方式 | 效果 |
|------|------|----------|------|
| 力量+ | Buff | 强度叠层 | 每层攻击伤害 +1 |
| 敏捷+ | Buff | 强度叠层 | 每层格挡 +1 |
| 格挡 | — | （走 ResourceManager） | 吸收伤害，回合结束清零 |
| 易伤 | Debuff | 强度叠层 | 每层受到伤害 +25% |
| 虚弱 | Debuff | 强度叠层 | 每层造成伤害 -25% |
| 缠绕 | Debuff | 持续回合 | 无法出攻击牌（N 回合） |
| 中毒 | Debuff | 强度叠层 | 回合结束扣 N HP → 层数 -1 |
| 灼烧 | Debuff | 强度叠层 | 回合结束扣 N HP → 层数 -1 |
| 流血 | Debuff | 强度叠层 | 出攻击牌时扣 N HP → 层数 -1 |
| 石化 | Debuff | 持续回合 | 无法出牌（N 回合） |
| 恐惧 | Debuff | 持续回合 | 随机弃牌 N 张/回合 |
| 免疫 | Buff | 持续回合 | 免疫中毒+流血（不受层数叠加，仅持续） |
| 闪避 | Buff | 强度叠层 | 每层 50% 闪避下次攻击，闪避后 -1 层 |
| 穿透 | Buff | 强度叠层 | 每层穿透 1 点格挡 |
| 反伤 | Buff | 强度叠层 | 被攻击时对攻击者造成 N 伤害 |

### 5.3 角色专属状态

| 状态 | 角色 | 叠层方式 | 效果 |
|------|------|----------|------|
| 冰霜 ❄️ | 墨夜（施加于敌人） | 强度叠层，上限 10 | 每层使敌人伤害 -5%；8 层触发冻结（跳过下回合），冻结后清零 |
| 冻结 🧊 | 墨夜（施加于敌人） | 持续 1 回合 | 跳过该敌人的下一个回合，到期后冰霜清零 |
| 荆棘 🌿 | 叶默（自身） | 强度叠层，无上限 | 回合结束对所有敌人造成 N 伤害 |
| 标记 🎯 | 温静（施加于敌人） | 持续 2 回合 | 对被标记敌人伤害 +25% + 暴击率 +15% |
| 复仇 💢 | 盛元（自身） | 强度叠层 | 每损失 5HP 获 1 层，每层下一张攻击 +2 伤，打出后清零 |
| 神罚蓄能 ✨ | 金英（自身） | 蓄能型 | 治疗量累计为蓄能值，通过卡牌转化为神圣伤害 |
| 亲和 💚 | 金英（自身） | 状态标记 | 回合结束若本回合未受伤 → 回复 2HP |
| 战甲模式 🤖 | 莉莲（自身） | 二态切换 | 攻击模式（+30%伤害/-2HP 回合结束）↔ 防御模式（+30%格挡/+2HP） |
| 过热 ⚙️ | 莉莲（自身） | 计数器 | 切换 3 次触发，下回合不可切换但 +2力+2敏 |
| 连击计数 ⚡ | 温静（自身） | 计数器 | 每打出 3 张攻击牌触发连击效果 |
| 丧尸随从 🧟 | 红发（友方格） | 实体召唤 | 独立 HP 的友方单位，每回合自动攻击 |
| 恐惧控制 😱 | 红发（施加于敌人） | 持续回合 | 敌人随机跳过行动 |

### 5.4 StatusManager 接口

```gdscript
# StatusManager 公共方法
apply_status(target, status_id: String, stacks: int, duration: int = -1)
remove_status(target, status_id: String)
get_stacks(target, status_id: String) -> int
has_status(target, status_id: String) -> bool
clear_all_statuses(target)           # 冻结触发时使用
tick_statuses(target)                # 回合结束：处理tick_effect → duration-1 → 移除到期

# 信号
status_applied(target, status_id: String, stacks: int)
status_removed(target, status_id: String)
status_ticked(target, expired_list: Array)
freeze_triggered(target)             # 墨夜冻结
thorn_damage(target, damage: int)    # 叶默荆棘
```

### 5.5 关键约束

1. 状态结算顺序（回合结束）：中毒/灼烧 tick → Duration-1 → 移除到期状态 → 荆棘结算
2. 禁止叠层超过 max_stacks（冰霜上限 10 层等）
3. 敌人/玩家共用一个 StatusManager，通过 target 区分
4. 易伤和虚弱相互抵消——结算时先计算净层数
5. 同一状态多次施加：INTENSITY 型增加层数（不超过 max），DURATION 型重置回合数
6. "无法出牌"类状态（石化/冻结）优先级最高，覆盖一切出牌操作

## 6. 敌人 AI 系统

### 6.1 敌人数据结构

```gdscript
# EnemyData Resource
id: String
display_name: String
base_hp: int                       # 基础 HP（实际 HP = base × 章节倍率 × Ascension 修正）
enemy_type: Enum                   # NORMAL / ELITE / BOSS
phase_configs: Array[PhaseConfig]  # Boss 多阶段配置（普通敌人为空）
intent_pattern: Array[IntentData]  # 意图循环序列
crystal_drop: int                  # 魔晶掉落
resistant_statuses: Dictionary     # 状态抗性 {"freeze": 0.5, "poison": 1.0}
```

### 6.2 意图系统实现

```gdscript
# EnemyAI（每只敌人独立实例）

# 本回合结束时调用
func generate_next_intent():
  1. 从 intent_pattern[pattern_index] 读取意图模板
  2. 当前 HP 检查阶段切换（Boss）
  3. 计算实际数值：
     actual_value = base_value × 章节倍率 × Ascension修正 × (1 ± value_variance)
  4. 信号广播：enemy_intent_revealed(enemy, intent_data)
  5. pattern_index = (pattern_index + 1) % intent_pattern.size()

# 敌人回合执行时调用
func execute_intent():
  1. 读取当前 intent_data
  2. 按类型分发：
     ATTACK  → EffectResolver.execute_damage(target, actual_value)
     DEFEND  → ResourceManager.modify_block(self, actual_value)
     BUFF    → StatusManager.apply_status(self, status_id, secondary_value, status_duration)
     DEBUFF  → StatusManager.apply_status(target, status_id, secondary_value, status_duration)
     SUMMON  → EnemyManager.spawn_enemy(spawn_id, secondary_value, position)
     SPECIAL → 触发 special_rules 中注册的逻辑
  3. 信号广播：enemy_acted(enemy, intent, result)
```

### 6.3 Boss 多阶段管理

```gdscript
# BossPhaseManager（挂载于 Boss 敌人）

# 监听 HP 变化
func _on_hp_changed(enemy, current_hp, max_hp):
  var hp_ratio = float(current_hp) / max_hp
  for phase in phase_configs:
    if hp_ratio <= phase.hp_threshold and not phase.triggered:
      trigger_phase_change(phase)

func trigger_phase_change(phase: PhaseConfig):
  1. 暂停意图循环
  2. 播放 phase.phase_animation（0.5-1.5s）
  3. 清除 phase.clear_statuses_on_enter 中列出的状态
  4. 替换 intent_pattern = phase.new_intent_pattern
  5. pattern_index 重置为 0
  6. 生成第一个新意图
  7. 信号广播：boss_phase_changed(boss, phase_index)
```

### 6.6 关键约束

1. 意图必须在上一回合明示，不可隐藏（Boss 范围值除外——显示 "12~18"）
2. 多只敌人时，按生成顺序（slot 顺序）依次执行意图

4. Boss 阶段切换期间暂停所有计时和意图执行

7. 特殊敌人抗性（如冰霜抗性 0.5 = 施加冰霜层数 × 0.5，向下取整）

### 7.3 叶默 · 锻造 + 荆棘

**锻造逻辑：**
- 锻造卡牌：复制原卡实例 → 修改数值(+30-50%) → 标记 `is_forged = true` → 放回手牌
- 每张卡最多锻造 1 次（通过"大师锻造"等能力可增加锻造次数上限）
- 锻造后的数值在牌堆循环中**保留**（进弃牌堆/抽牌堆后仍是锻造版本）
- 营地永久升级 + 锻造叠加：两者独立计算，伤害 = (基础+升级增量) × (1+锻造增量%)
- 锻造次数追踪：CardData.forge_count（"瞬间锻造"等卡牌读取该值）

**荆棘逻辑：**
- `on_turn_end()`: EnemyManager.get_alive_enemies() → 每只敌人 damage = 荆棘层数
- "自然之怒"卡牌：EffectResolver 读取荆棘层数 → damage = 层数 × 3

**初始遗物（自然之杖）：**
- `on_battle_start()` → add_card_to_hand(生成"生长"卡：0费·3甲+升级1张手牌)

### 7.4 墨夜 · 冰霜 + 天怒

**冰霜逻辑：**
- 冰霜施加于敌人 → 每层 -5% 敌人造成的伤害
- `on_damage_dealt(source=敌人)`: `modified_damage = damage × (1 - 0.05 × frost_stacks)`
- 冰霜 ≥ 8 层 → 触发冻结：StatusManager.clear_all_statuses(敌人) + 跳过下回合的意图执行
- 冻结状态持续 1 回合，到期后敌人恢复行动
- 初始遗物（冰晶护符）：`on_status_applied(target, "frost")` → 计数器++ → 每3层+1精神力（每回合最多2次）

**天怒逻辑：**
- 带"天怒"标签的卡牌，每场战斗首次使用伤害 ×2
- `on_card_played(card)`: if "天怒" in card.keywords and not fury_used → 设置倍率 2.0 → fury_used = true

### 7.5 温静 · 标记 + 连击

**标记逻辑：**
- 标记施加于敌人：StatusManager.apply_status(enemy, "mark", 1, 2)
- `get_extra_damage(target)`: if target.has_status("mark") → +25% damage + 15% 暴击判定
- 部分卡牌"引爆"标记：remove_status → 造成额外伤害（伤害 = 固定值 + 标记剩余回合 × N）
- 初始遗物（玫瑰印记）：`on_damage_dealt(target)` + target.has_status("mark") → 每回合首次追加3点伤害

**连击逻辑：**
- `on_card_played(card)` + card.type == ATTACK → combo_counter++
- `if combo_counter % 3 == 0` → 触发连击效果池
- 效果池可配置：抽1张 / +1精神力 / 全体4伤害（可通过遗物扩展）
- 卡牌"连击计数"遗物：触发阈值从 3 降至 2

### 7.6 盛元 · 复仇 + 血祭

**复仇逻辑：**
- `on_damage_taken(target=self, amount)`: `revenge_stacks += floor(amount / 5)`
- `get_extra_damage()`: `revenge_stacks × 2` → 加到下一张攻击牌
- `on_card_played(ATTACK)`: `revenge_stacks = 0`（清零）
- 初始遗物（亡者意志）：`on_turn_start()` → HP<50% → +1精神力；HP<25% → +2精神力

**血祭逻辑：**
- 卡牌打出时 cost_hp > 0：先扣 HP → 再执行卡牌效果
- HP 不足 cost_hp 时：不能打出（卡牌灰色）
- 血祭型卡牌的效果数值通常比同费卡高 30-50%

### 7.7 金英 · 神罚 + 亲和

**神罚逻辑：**
- 神圣伤害：在 EffectResolver.EXECUTE 阶段走 HOLY_DAMAGE 分支 → 跳过格挡扣除
- `on_heal(target=self, amount)`: `holy_charge += amount`
- 神圣输出卡牌的 Effect.type = SPECIAL → 消耗 holy_charge 转化为伤害
- 初始遗物（神圣之触）：每回复 4HP → 随机敌人受 3 神圣伤害

**亲和逻辑：**
- `on_turn_end()`: if 本回合 damage_taken == 0 → reply 2HP
- 遗物"神罚使者之印"：将条件放宽为 damage_taken ≤ 3

### 7.8 红发 · 召唤 + 牺牲

**召唤逻辑：**
- 丧尸随从在友方格生成（max 4 个，遗物 +1 = 5）
- 每只丧尸：独立 HP(5-20) + 每回合自动攻击随机敌人(damage 3-8)
- `on_turn_end()`: EnemyManager.ally_auto_attack_all()
- 丧尸死亡 → `on_ally_killed()`: ResourceManager.modify_block(player, 2)
- 初始遗物（意识结晶）：`get_extra_block()` = 存活丧尸数（最多 +4）

**牺牲逻辑：**
- "狂物之鸣"：读取 alive_allies → remove_all() → 每只对全体敌人造成 8 伤害
- "狂物核心"遗物：每只牺牲 → 额外 +3 伤害

### 7.9 莉莲 · 战甲 + 过热

**战甲模式逻辑：**
- 当前模式：StatusManager 追踪 "attack_mode" / "defense_mode"
- 初始遗物（机械战甲核心）：每回合免费切换 1 次，额外切换 1 精神力

```
攻击模式：
  get_extra_damage(): +30%
  on_turn_end(): HP -2

防御模式：
  get_extra_block(): +30%
  on_turn_end(): HP +2
```

**双面卡：**
- 卡牌 Effect 分两组：attack_mode_effects / defense_mode_effects
- 打出时根据当前模式选择对应 Effect 组执行

**过热逻辑：**
- 切换计数器（switch_counter），每切换 1 次 +1
- switch_counter 达到 3 → 触发过热：下回合 on_turn_start() 时不可切换 + +2力量 + +2敏捷
- 过热结束后 switch_counter 清零

**遗物修正：**
- 散热模块：过热阈值从 3 → 4
- 攻击/防御增幅器：模式加成从 +30% → +45%

### 7.10 关键约束

1. 每场战斗只加载当前角色对应的 Mechanic 实例（不实例化其他角色代码）
2. Mechanic 方法在结算管道的固定时机被 BattleManager 调用，不直接修改其他模块状态
3. 新增角色 = 新建继承 BaseMechanic 的脚本 + 注册到角色枚举 → 无需修改框架
4. 角色机制与卡牌 keyword 系统联动——卡牌打上对应标签后自动被 Mechanic 识别
5. 角色专属状态（冰霜/标记/复仇等）仅当对应 Mechanic 加载时才向 StatusManager 注册

### 8.4 触发实现

```gdscript
func trigger(timing: String, context: Dictionary):
  for relic in relics:
    if relic.trigger_timing == timing:
      # 检查充能
      if relic.max_charges > 0 and relic.current_charges < relic.charges_per_trigger:
        continue
      # 检查条件
      if not relic.trigger_condition.is_empty() and not check_condition(relic.trigger_condition, context):
        continue
      # 消耗充能（如有）
      if relic.max_charges > 0:
        relic.current_charges -= relic.charges_per_trigger
      # 执行效果
      for effect in relic.effect:
        EffectResolver.execute(effect, context)
      relic_triggered.emit(relic, result)
```

### 9.2 装备槽管理

```gdscript
# EquipmentManager（CardManager 子模块）
slots: Dictionary = {
  "WEAPON": null,     # null | EquipmentCardData
  "ARMOR": null,
  "ACCESSORY": null
}

func equip(card: EquipmentCardData):
  var slot = card.equipment_slot
  if slots[slot] != null:
    unequip(slots[slot])              # 旧装备卸下 → 入消耗堆
  slots[slot] = card
  EffectResolver.execute(card.on_equip_effect)   # 触发装备瞬间效果
  equipment_equipped.emit(card, slot)

func unequip(card: EquipmentCardData):
  EffectResolver.execute(card.on_unequip_effect)  # 触发卸下效果
  slots[card.equipment_slot] = null
  card → 入消耗堆
  equipment_unequipped.emit(card, card.equipment_slot)

func get_slot_bonus(slot: String) -> Array[Effect]:
  if slots[slot] == null:
    return []
  return slots[slot].active_effect
```

### 9.3 与结算管道集成

```
get_extra_damage(target) 计算时:
  基础 = 力量 × 1 + 其他 Buff 修正
  + 武器槽 active_effect 遍历求和（FILTER: type==DAMAGE 的 Effect）
  + 饰品槽 active_effect 遍历求和（FILTER: type==DAMAGE 的 Effect）

get_extra_block() 计算时:
  基础 = 敏捷 × 1 + 其他 Buff 修正
  + 防具槽 active_effect 遍历求和（FILTER: type==BLOCK 的 Effect）
```

### 9.4 装备卡示例

| 装备卡 | 槽位 | active_effect | 特殊 |
|--------|------|--------------|------|
| 战刃·沙尘(形态1) | WEAPON | [MODIFY_STAT: +1力, DAMAGE: +3伤·每回合1次] | — |
| 战刃·沙尘(形态2) | WEAPON | [MODIFY_STAT: +2力, DAMAGE: +6伤·每回合1次] | 沙尘特效 |
| 战刃·沙尘(终极) | WEAPON | [MODIFY_STAT: +3力, DAMAGE: 10伤暴击·每回合1次, HEAL: 2·每次攻击] | 传说 |
| 臂盾 | ARMOR | [BLOCK: +3·每回合开始] | — |
| 弩 | WEAPON | [DAMAGE: 6·远程·每2回合] | 远程免反伤 |

### 9.5 关键约束

1. 每个槽位最多 1 件装备，新装备旧自动替换
2. 替换的旧装备入消耗堆，不可重新装备（除非特殊遗物）
3. 装备卡打出后不经过弃牌堆——直接入装备槽 + 消耗
4. 耐久度归零 → 装备自动卸下入消耗堆
5. 装备 active_effect 在每回合的计算中都会重新读取（支持动态修改）

## 10. 战斗奖励 & 战斗收尾

### 10.1 奖励计算流程

```
战斗胜利结算（所有敌人死亡 → BATTLE_WIN 状态）:

1. 魔晶结算：
   for each dead_enemy:
     total_crystals += dead_enemy.crystal_drop
   应用遗物修正（采集手套 +1/只等）
   ResourceManager 中的魔晶传递至 MapLevel（用于后续轮盘节点）

2. 奖励生成（根据敌人类型）:
   - 普通战:
     card_choices = 随机3张卡（稀有度权重: 白60/绿25/蓝10/紫4/橙1）
     can_skip_card = true
     relic_drops = []（不掉遗物）
     
   - 精英战:
     card_choices = 随机3张卡（稀有度权重: 绿50/蓝35/紫12/橙3）
     can_skip_card = true
     relic_drops = 60%概率掉 1 个遗物（稀有度权重: 白60/绿25/蓝10/特殊5）
     
   - Boss战:
     card_choices = 随机3张稀有+卡（稀有保底, 33%史诗/传说）
     can_skip_card = false
     relic_drops = 1 个 Boss 遗物（3选1）+ 章节通关奖励

3. HP 回复（非Boss战）：回复量受遗物修正
4. 奖励展示 → 玩家选择 → 更新角色牌组/遗物列表

5. 战斗数据记录：
   - 总回合数
   - 总伤害输出
   - 总格挡获取
   - 击杀数
```

### 10.2 奖励数据结构

```gdscript
# BattleReward
crystals: int
card_choices: Array[CardData]       # 3选1（遗物修正可增至4选1）
can_skip_card: bool                 # 普通战可跳过
relic_options: Array[RelicData]     # 遗物（Boss遗物为3选1）
hp_restore: int                     # 战斗后回复量
```

### 10.3 战败处理

```
BATTLE_LOSE:

1. 死亡动画（1-2s）
2. 弹出死亡选项菜单：
   ┌─────────────────────────────┐
   │  💀 你死了                    │
   │                              │
   │  [从本章开头重开]             │
   │  （恢复章节存档时的状态）       │
   │                              │
   │  [从第一章完全重开]            │
   │  （清除所有进度）              │
   │                              │
   │  [返回主菜单]                 │
   └─────────────────────────────┘

3. Ascension 模式：跳过选项 → 直接完全重开（无章节重试）
4. 非 Ascension 模式下，选择"从本章开头重开" → 恢复该章存档时的牌组/遗物/HP 快照
5. 战斗数据不入统计（除非触发了成就条件）
```

### 10.4 关键约束

1. 魔晶在战斗胜利后转入局外（MapLevel 层），战斗模块本身不存储跨战斗魔晶
2. Boss 战奖励必选卡牌（can_skip_card = false）
3. 遗物"秘境钥匙碎片"：精英战卡牌选择从 3 选 1 升级为 4 选 1
4. 遗物"圣城之印"：精英战后奖励选 2 次，普通战不再奖励卡牌选择
5. 奖励界面为独立 UI 层，弹出时暂停战斗场景

### 11.3 交互流程

```

1. Hover 卡牌 → CardWidget 放大展示 + 费用高亮
   若 energy < card.cost → 卡牌灰色半透明 + 费用红色

2. 点击卡牌：
   - 无目标类型(SELF/ALL_ENEMIES/ALL_ALLIES) → 立即调用 CardManager.play_card()
   - 需目标类型(SINGLE_ENEMY/RANDOM_ENEMY) → 卡牌悬停 + TargetSelector 激活

   - 可选目标：高亮闪烁（金色边框）
   - 不可选目标：灰色蒙版

4. 打出动画序列:
   ① 卡牌从手牌位置飞向目标（0.15s）
   ② 目标受击闪白/击退/震动

   - PLAYER_PLAY 状态始终可用
   - 点击后：若有待确认的选择 → 取消 → 弃所有手牌
   - 转入 PLAYER_TURN_END
```

### 12.2 关键路径信号流

```
玩家打出"斩击"→ 敌人A：

CardWidget.card_selected("斩击")
  → TargetSelector 激活 → 玩家点击 敌人A
  → CardManager.play_card("斩击", enemy_A)
    → ResourceManager.modify_energy(-1)
      → energy_changed.emit()
    → RelicManager.trigger("ON_CARD_PLAYED", {card, target: enemy_A})
      → relic_triggered.emit(relic, ...)  # 如有匹配遗物
    → EffectResolver.execute(card.effects, target: enemy_A)
      → effect_about_to_execute.emit(effect, enemy_A)
      → damage_about_to_apply.emit(enemy_A, 6+strength)
      → damage_applied.emit(enemy_A, raw=9, actual=5, blocked=4)
        → ResourceManager.modify_hp(enemy_A, -5)
          → hp_changed.emit(enemy_A, 35, 40, -5)
          → EntityArea 血条动画
    → RelicManager.trigger("ON_DAMAGE_DEALT", {source: player, target: enemy_A, amount: 5})
    → CharacterMechanic.on_damage_dealt(player, enemy_A, 5)
    → KILL_CHECK:
      if enemy_A.hp <= 0:
        → ResourceManager.entity_died(enemy_A, player)
        → EnemyManager.enemy_killed(enemy_A, 1)
          → crystals_changed.emit()
        → RelicManager.trigger("ON_KILL", {killer: player, target: enemy_A})
        → CharacterMechanic.on_kill(enemy_A, true)
  → card_played.emit("斩击", enemy_A)
  → CardManager.discard_card("斩击")
  → HUD 更新完毕
```

### 12.3 信号规范

1. 命名规则：过去式表示"已发生"，`_about_to` 后缀表示"即将发生（可拦截/修正）"
2. 所有 signal 携带足够 context（Dictionary），避免监听者回查状态管理器
3. 避免信号循环——A 触发 B 触发 C 不应再触发 A
4. 性能敏感路径：全屏 AOE 伤害时，合并同类信号为 batch 发送（如 `damage_applied` 传 targets: Array 而非逐个 emit）
5. `_about_to` 类信号携带可变引用，EffectResolver 在调用后读取修改值作为最终结算值

| 风险 | 严重程度 | 缓解措施 |
|------|----------|----------|
| 7角色机制复杂度导致 BaseMechanic 接口膨胀 | 中 | 使用 Dictionary context 传递，基类方法提供默认空实现 |
